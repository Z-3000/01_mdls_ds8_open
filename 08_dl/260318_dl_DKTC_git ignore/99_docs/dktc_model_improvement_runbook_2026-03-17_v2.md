## 1. 문서 목적

이 문서는 이번 세션에서 진행한 DKTC 위협 대화 분류 모델 개선 작업을 세션 종료 이후에도 이어갈 수 있도록 정리한 운영 문서다.

정리 범위는 다음과 같다.

1. 사용한 데이터와 전처리 파이프라인
2. 시도한 모델/손실함수/하이퍼파라미터 실험
3. 실험별 성능 변화
4. 현재 병목 해석
5. 바로 이어서 해야 할 실험 우선순위
6. 외부 벤치마크 사례와 현재 과제에 주는 시사점

본 문서는 **이번 세션에서 실제로 확인된 값**과 **공식/공개 자료에서 확인 가능한 벤치마크 사례**만 사용했다. 확정할 수 없는 부분은 추정으로 단정하지 않았다.

## 5. Focal Loss 실험 요약

### 5.1 실험 목적

가설:
- 일반대화는 상대적으로 쉬운 샘플일 가능성이 높다.
- 협박/갈취/기타괴롭힘은 경계가 애매한 hard sample이 많다.
- 따라서 Focal Loss를 사용하면 쉬운 샘플 기여를 줄이고 hard sample 학습을 강화할 수 있다.

### 5.2 실험 조건

기본 focal 설정:
- gamma = 2.0
- class weight 사용 여부 비교
- learning rate / epoch / weight decay / warmup / scheduler 실험

총 11개 실험 수행.

### 5.3 전체 결과

### 5.4 best 모델 상세

Best: `focal_epoch_5`
- Accuracy: 0.9298
- Macro F1: 0.9301
- Weighted F1: 0.9302

클래스별 F1:
- 협박: 0.9186
- 갈취: 0.8990
- 직장내괴롭힘: 0.9634
- 기타괴롭힘: 0.8794
- 일반대화: 0.9899

오분류 68 / 969 = 7.0%

주요 오분류 패턴:
- 기타괴롭힘 → 갈취: 20
- 협박 → 갈취: 11
- 협박 → 기타괴롭힘: 8
- 직장내괴롭힘 → 기타괴롭힘: 7
- 기타괴롭힘 → 협박: 5

### 5.5 sanity check

- 검증셋 969개에서 오분류 68건이면 정분류 901건
- `901 / 969 = 0.9298`로 reported accuracy와 일치
- 클래스별 F1 평균도 약 0.9301로 macro F1과 일치

### 5.6 해석

1. **Focal Loss 실험 공간의 최고점은 non-focal 최고점보다 높다.**
   - non-focal best: 0.9265
   - focal best: 0.9301
   - 차이: **+0.0036 macro F1**

2. 하지만 개선 원인을 단순히 "Focal Loss 때문"이라고 단정하기는 어렵다.
   - epoch 5의 기여가 크다.
   - lr 5e-5, cosine도 유효했다.
   - 즉 **loss와 학습 스케줄 조합 효과**로 보는 것이 더 정확하다.

3. Focal Loss를 써도 병목은 그대로다.
   - 일반대화는 여전히 강함
   - 가장 약한 클래스는 여전히 `기타괴롭힘`
   - 핵심 혼동축도 계속 유지됨

4. `gamma` 튜닝은 1순위 변수가 아니었다.
   - gamma 1.5, 2.0, 2.5 간 큰 차이 없음
   - 현재 근거상 `1.5~2.0` 범위면 충분

5. class weight 효과는 미미하거나 불리할 가능성이 있다.
   - focal baseline(가중치 사용): 0.9176
   - focal_no_cw(가중치 미사용): 0.9220
   - 단, 단일 split 결과이므로 확정적 결론은 아님

## 6. 현재까지의 종합 판단

### 6.1 확실한 것

- `klue/roberta-base`는 현재 데이터에서 이미 강한 베이스라인이다.
- 데이터 전처리와 균형 조정은 일정 수준 이상 잘 작동했다.
- 일반대화 분류는 이미 매우 강하다.
- 진짜 병목은 괴롭힘 내부 클래스 경계다.
- 특히 `기타괴롭힘`이 가장 어려운 클래스다.

### 6.2 확실하지 않은 것

- Focal Loss가 public/private leaderboard에서도 항상 더 낫다고 단정할 수는 없다.
- 현재 결과는 단일 validation split 기준이다.
- Kaggle test 분포가 다르면 `일반대화` 비중 변화에 따라 모델 유불리가 바뀔 수 있다.

### 6.3 현재 최선의 해석

지금 단계에서 모델 개선은 **더 큰 backbone 탐색**보다 아래 축이 더 중요하다.

1. 괴롭힘 내부 클래스 경계 강화
2. 추론 시 경계 샘플 후처리
3. 여러 성향 모델 준비 후 leaderboard 반응 확인

## 8. 다음 세션에서 바로 이어서 할 일

우선순위는 아래 순서가 맞다.

### 8.1 1순위 — 최고 3개 후보 모델 보존

즉시 후보로 유지할 모델:
1. `focal_epoch_5`
2. `focal_lr_5e-5`
3. `focal_cosine`

이유:
- 성능 상위권
- 서로 성향이 다름
- Kaggle public/private 분포 차이에 대응하기 좋음

### 8.2 2순위 — 규칙 기반 후처리(logit adjustment)

목표:
- `협박 ↔ 갈취`
- `기타괴롭힘 ↔ 갈취`
- `직장내괴롭힘 ↔ 기타괴롭힘`
혼동 축 완화

추천 방식:
- 학습 데이터는 그대로 유지
- 추론 시 top1-top2 margin이 작을 때만 규칙 점수 추가
- 예시 규칙
  - 협박 신호: 해악 예고 표현
  - 갈취 신호: 요구/대가/금전/행동 강요 표현
  - 직장내괴롭힘 신호: 회사/상사/업무/평가/보고 문맥

### 8.3 3순위 — 2단계 분류 실험

1단계:
- 일반대화 vs 괴롭힘

2단계:
- 협박 / 갈취 / 직장내괴롭힘 / 기타괴롭힘

현재 결과상 일반대화는 이미 잘 맞으므로,
문제를 두 단계로 나눠 괴롭힘 내부 분리를 더 집중시키는 전략이 타당하다.


### 8.2A 규칙 기반 후처리 시도 상세 로그 (이번 세션 추가)

이번 세션에서는 `focal_epoch_5` 체크포인트를 기준 모델로 사용해, 검증셋 raw logits에 대해 규칙 기반 logit adjustment를 별도 노트북으로 실험했다. 목적은 모델을 다시 학습하지 않고도 **경계 샘플에서 혼동축 오분류를 줄일 수 있는지** 확인하는 것이었다.

#### 시도 1 — v1 초안
핵심 아이디어:
- softmax 기준 top1-top2 margin이 작은 샘플만 후보로 선택
- 클래스별 키워드 정규표현식 사전을 정의
- 매칭된 클래스 logits에 고정 boost를 추가
- 검증셋에서 `margin_threshold × boost_per_hit` ablation 수행

문제점:
1. 타겟 혼동축이 아닌 샘플에도 개입할 수 있었다.
2. top2 후보 이외의 제3클래스에도 boost가 들어갈 수 있었다.
3. 확률 margin으로 후보를 고르고 logit에 고정값을 더해 스케일 해석이 어색했다.
4. 정규식이 넓어서 precision 저하 위험이 컸다.
5. 같은 validation에서 best 후처리 파라미터를 고르면 과적합 위험이 있었다.

판단:
- 분석 프로토타입으로는 유용했지만, 그대로 제출용 최종 로직으로 쓰기에는 논리적 안전장치가 부족했다.

#### 시도 2 — v2 개선안
v1의 핵심 문제를 줄이기 위해 아래를 반영했다.

1. **타겟 혼동축에서만 개입**
   - `(협박, 갈취)`, `(갈취, 기타괴롭힘)`, `(직장내괴롭힘, 기타괴롭힘)`에 해당할 때만 개입
2. **top2 내 후보 클래스만 보정**
   - 전역 5개 클래스 검색이 아니라 현재 경쟁 중인 후보 클래스들만 고려
3. **정규식 축소**
   - 일상대화에서도 흔히 나오는 넓은 패턴 제거
4. **validation 과적합 경고 명시**
   - 로컬 ablation 결과는 참고용으로만 보고, 원본 모델과 후처리 모델을 별도 제출 후보로 보관

판단:
- 설계 의도와 구현 일치도는 올라갔다.
- 다만 여전히 규칙 정보량이 적고, 실제로 예측을 뒤집는 샘플 수가 많지 않을 가능성이 남아 있었다.

#### 시도 3 — v3 공격적 버전
v2보다 조금 더 공격적으로 가기 위해 아래를 도입했다.

- `topk_candidates=3`
- 타겟 혼동축 내에서 top-k 후보 중 규칙 hit가 있는 클래스만 고려
- 샘플별 `top1-top2 logit gap`에 비례한 boost 사용
- `margin_threshold`를 0.30에서 시작해 0.35, 0.40까지 확대

실제 확인된 결과는 아래와 같다.

##### v3 baseline 기준 성능
- 후처리 전:
  - Accuracy: **0.9298**
  - Macro F1: **0.9301**
  - Weighted F1: **0.9302**
  - 오분류: **68 / 969**

##### v3 후처리 결과 (`margin_threshold=0.35`)
- 후처리 후:
  - Accuracy: **0.9309**
  - Macro F1: **0.9310**
  - Weighted F1: **0.9310** 내외
  - 오분류: **67 / 969**
- 실제 예측 변경: **1건**
- 순효과: **개선 1건 / 악화 0건**
- 바뀐 사례:
  - **기타괴롭힘 → 갈취** 로 바뀌었고, 정답이 갈취라서 개선 1건

##### v3 후처리 결과 (`margin_threshold=0.40`)
- 결과가 `0.35`와 **동일**
  - Accuracy: **0.9309**
  - Macro F1: **0.9310**
  - 오분류: **67 / 969**
  - 실제 예측 변경: **1건**

##### v3 gate 통과 수 (0.35 / 0.40 공통 확인값)
- 전체 샘플: **969**
- Gate1 통과(경계 샘플): **40**
- Gate2 통과(타겟 혼동축): **28**
- Gate3 통과(규칙 hit 존재): **13**
- Gate4 통과(실제 보정 후보): **12**
- 최종 예측 변경: **1**

#### 규칙 기반 후처리 실험 해석
핵심 해석은 다음과 같다.

1. **후처리가 모델을 망치지는 않았다.**
   - 로컬 validation 기준으로 악화 없이 +1건 개선이 있었다.
2. **하지만 영향력은 매우 작았다.**
   - threshold를 0.35, 0.40으로 올려도 결과가 같았다.
3. **병목은 threshold가 아니었다.**
   - 후보 수를 약간 늘려도 실제로 예측을 뒤집을 수 있는 샘플이 거의 없었다.
4. **문제는 규칙 정보량과 태스크 의미 경계다.**
   - 남은 오분류 상당수는 단순 키워드보다 대화 맥락과 클래스 경계 정의에 더 민감한 사례로 보인다.
5. **규칙 후처리는 보조 후보로는 유지 가능하지만, 주력 개선 축으로 보기 어렵다.**

실무 판단:
- 규칙 기반 후처리는 **제출 후보 1개 추가** 정도의 의미는 있다.
- 하지만 이번 세션 결과만 보면, 시간을 더 써서 키워드/threshold를 미세조정하는 것보다 **2단계 분류 구조 실험**이 우선순위가 더 높다.

### 8.3A 2단계 분류 프로토타입 구현을 위해 필요한 사항

이 절은 세션 종료 후에도 문서만 보고 바로 프로토타입을 만들 수 있도록 **필요 데이터, 구현 순서, 평가 기준, 실패 기준**까지 적는다.

#### 목표
현재 병목은 `일반대화 vs 괴롭힘`이 아니라 **괴롭힘 내부 4개 클래스 경계**다.  
따라서 문제를 두 단계로 쪼갠다.

- **Stage 1:** `일반대화` vs `괴롭힘`
- **Stage 2:** `협박 / 갈취 / 직장내괴롭힘 / 기타괴롭힘`

#### 왜 필요한가
현재 검증 결과상 `일반대화` F1은 약 **0.9899**로 이미 매우 높다.  
즉 5-class 단일 모델이 한 번에 두 가지를 같이 풀고 있다.

1. 일반대화인지 아닌지 구분
2. 괴롭힘이면 어느 유형인지 구분

이 중 1번은 이미 쉬운 문제에 가깝고, 2번이 진짜 병목이므로 **문제를 분리하는 것이 논리적으로 맞다.**

#### 구현 전 준비물
반드시 준비되어 있어야 하는 파일과 정보:
- `data/train_processed_260317_n_1000.csv`
- `data/val_processed_260317_n_1000.csv`
- 현재 best 설정 메모
  - 모델: `klue/roberta-base`
  - `max_length=512`
  - focal best 기준: `focal_epoch_5`
- 라벨 매핑 표
  - 협박 = 0
  - 갈취 = 1
  - 직장내괴롭힘 = 2
  - 기타괴롭힘 = 3
  - 일반대화 = 4

#### 데이터셋 생성 규칙

##### Stage 1용 binary 데이터셋
원본 train/val을 그대로 복사한 뒤 binary label을 만든다.

- `label_bin = 0` if 원래 라벨이 일반대화(4)
- `label_bin = 1` if 원래 라벨이 괴롭힘(0,1,2,3)

예시 코드:
```python
train_bin = train_df.copy()
val_bin = val_df.copy()

train_bin["label_bin"] = (train_bin["label"] != 4).astype(int)
val_bin["label_bin"] = (val_bin["label"] != 4).astype(int)
```

##### Stage 2용 harm-only 4-class 데이터셋
원본 train/val에서 일반대화(4)를 제거한다.

```python
train_harm = train_df[train_df["label"] != 4].copy()
val_harm = val_df[val_df["label"] != 4].copy()
```

Stage 2 라벨은 그대로 유지해도 되지만, 0~3 범위인지 반드시 확인한다.
현재 DKTC 라벨 체계에서는 이미 0~3이므로 재매핑이 필요 없을 가능성이 높다. 단, 코드에서 `num_labels=4`로 줄이면 라벨 값이 실제로 0~3 범위인지 다시 확인해야 한다.

#### 구현 순서

##### Step 1. Stage 1 모델 학습
목표:
- 일반대화 vs 괴롭힘 binary 분류

권장 설정:
- 백본: `klue/roberta-base`
- `num_labels=2`
- 손실함수: 우선 CrossEntropy 또는 기존 focal 설정 중 단순한 쪽 1개만 사용
- 처음엔 규칙 후처리 없이 순수 모델만 검증

반드시 기록할 것:
- Accuracy
- Binary F1
- 일반대화 recall
- 괴롭힘 recall

이유:
- Stage 1에서 괴롭힘을 일반대화로 놓치면 Stage 2에 못 넘어가므로, **괴롭힘 recall**이 특히 중요하다.

##### Step 2. Stage 2 모델 학습
목표:
- 괴롭힘 4개 클래스 세부 분류

권장 설정:
- 백본: `klue/roberta-base`
- `num_labels=4`
- 우선 기존 best에 가까운 설정으로 시작
- 후보:
  - `focal_epoch_5` 계열
  - 혹은 non-focal `wd_0.1` 계열

반드시 기록할 것:
- Macro F1
- 클래스별 F1
- confusion matrix
- 특히 다음 혼동축 변화
  - 협박 ↔ 갈취
  - 갈취 ↔ 기타괴롭힘
  - 직장내괴롭힘 ↔ 기타괴롭힘

##### Step 3. Stage 1 + Stage 2 파이프라인 합성
최종 5-class 예측 생성 규칙:

1. Stage 1 예측이 `일반대화`면 최종 예측 = 4
2. Stage 1 예측이 `괴롭힘`이면 Stage 2 예측 결과 사용
   - Stage 2의 0/1/2/3을 최종 0/1/2/3으로 그대로 사용

주의:
- validation 평가 시 Stage 1과 Stage 2를 각각 따로 평가하는 것만으로는 부족하다.
- 반드시 **합성된 최종 5-class 성능**을 계산해야 한다.

##### Step 4. 단일 5-class 모델과 비교
아래 세 모델을 반드시 같은 validation에서 비교한다.

1. 단일 5-class best (`focal_epoch_5`)
2. 2단계 분류 파이프라인
3. 필요 시 단일 5-class + 규칙 후처리

비교 기준:
- Accuracy
- Macro F1
- Weighted F1
- 클래스별 F1
- 타겟 혼동축 감소 여부

#### 평가 기준

##### 성공 기준
아래 중 2개 이상을 만족하면 후보로 유지:
- 최종 5-class Macro F1이 기존 best와 같거나 높다.
- `기타괴롭힘`, `갈취`, `협박` 중 최소 2개 클래스 F1이 개선된다.
- 타겟 혼동축 오분류 총합이 감소한다.
- 일반대화 성능이 크게 악화되지 않는다.

##### 실패 기준
아래 중 하나라도 명확하면 우선순위를 낮춘다:
- Stage 1에서 괴롭힘을 일반대화로 놓치는 비율이 눈에 띄게 높다.
- 최종 5-class Macro F1이 기존 best보다 확실히 낮다.
- 일반대화 precision/recall이 깨진다.
- 파이프라인 합성 후 confusion pattern이 더 복잡해진다.

#### 구현 체크리스트

##### 필수
- [ ] `train_bin`, `val_bin` 생성
- [ ] `train_harm`, `val_harm` 생성
- [ ] Stage 1용 토크나이징/Trainer 함수 생성
- [ ] Stage 2용 토크나이징/Trainer 함수 생성
- [ ] 파이프라인 예측 합성 함수 작성
- [ ] 최종 5-class metric 함수 작성
- [ ] confusion matrix 출력
- [ ] 단일 5-class best와 표로 비교

##### 선택
- [ ] Stage 1에 focal loss 적용
- [ ] Stage 2에 focal / non-focal 둘 다 비교
- [ ] Stage 1 threshold 조절
- [ ] Stage 2 logits를 최종 confidence 분석에 활용

#### 구현 시 주의사항
1. **데이터 누수 금지**
   - Stage 1과 Stage 2 모두 동일한 train/val split 기준을 유지할 것
2. **라벨 재매핑 확인**
   - Stage 2에서 라벨이 0~3 범위인지 다시 확인할 것
3. **최종 평가는 파이프라인 기준**
   - Stage 1, Stage 2 단독 점수만 보고 결론 내리지 말 것
4. **처음부터 너무 많은 조합 금지**
   - Stage 1 1개, Stage 2 1~2개로 시작
5. **원본 단일 모델은 반드시 보존**
   - 2단계 분류가 실패할 가능성도 있으므로 비교 기준으로 남겨둘 것

#### 가장 현실적인 첫 실행안
시간이 많지 않다면 아래 조합부터 시작한다.

- Stage 1: `klue/roberta-base`, 2-label, 3 epoch, lr 2e-5
- Stage 2: `focal_epoch_5`와 유사한 설정 1개
- 최종 비교 대상:
  - 단일 5-class `focal_epoch_5`
  - 2단계 파이프라인 1개

이 조합으로도 충분히 **“2단계 분류가 구조적으로 먹히는지”**를 빠르게 판정할 수 있다.

### 8.4 4순위 — CV 안정화

현재 결과는 holdout 기반이다.
다음 세션에서는 최소 3-fold stratified validation으로 재검증하는 것이 좋다.

왜 필요한가:
- class weight 효과가 실제인지 확인
- focal 개선이 split-specific인지 확인
- Kaggle public overfitting 방지

### 8.5 5순위 — 데이터 재설계

지금 단계에서는 **일반대화를 무조건 더 늘리는 것**이 1순위가 아니다.
오히려 아래가 더 중요하다.

- 기타괴롭힘 경계 샘플 확보
- 갈취/협박을 헷갈리게 만드는 패턴 확인
- 직장 맥락이 있는 괴롭힘과 없는 괴롭힘 분리 강화

가장 현실적인 전략이다.

4. pseudo-labeling 제한적 도입

## 10. 벤치마크 사례와 시사점

### 10.1 OffensEval 2020 — 도메인 적응 MLM + Transformer

UHH-LT 팀은 OffensEval 2020에서 **in-domain MLM fine-tuning을 거친 RoBERTa 기반 분류기**로 영어 트랙 1위를 보고했다. 핵심 포인트는 단순 supervised fine-tuning만이 아니라, **실제 과제와 유사한 도메인 데이터로 MLM 추가 사전학습을 수행한 뒤 분류에 투입했다는 점**이다.

시사점:
- 현재 DKTC도 일반 한국어 문장 분류가 아니라 괴롭힘/위협 대화라는 도메인 특성이 강하다.
- 시간이 더 있다면 train+unlabeled text 기반의 domain adaptive pretraining(MLM)을 검토할 가치가 있다.
- 다만 1일 대회 직전에는 구현/검증 비용이 커서 우선순위는 낮다.

출처:
- ACL Anthology, *UHH-LT at SemEval-2020 Task 12*  
  https://aclanthology.org/2020.semeval-1.213/
- GitHub, `uhh-lt/uhhlt-offenseval2020`  
  https://github.com/uhh-lt/uhhlt-offenseval2020

### 10.2 Jigsaw / Unitary multilingual toxic model — 다중 과제 학습과 앙상블 지향

Unitary의 multilingual toxic XLM-RoBERTa 모델 카드는 이 모델이 **여러 Jigsaw toxic comment challenge 데이터**를 바탕으로 학습되었음을 설명한다. 독성 분류 계열 대회에서는 단일 모델보다 **다중 데이터/다중 단계 학습/앙상블**이 자주 쓰인다.

시사점:
- DKTC에서도 단일 최고점 모델 1개만 들고 가는 것보다
  - epoch 성향이 다른 모델
  - lr 성향이 다른 모델
  - cosine/linear 같은 스케줄이 다른 모델
  을 여러 개 보유하는 것이 실전적으로 유리하다.
- 현재 `focal_epoch_5`, `focal_lr_5e-5`, `focal_cosine`을 동시에 보존하는 판단은 이 방향과 맞다.

출처:
- Hugging Face model card, `unitary/multilingual-toxic-xlm-roberta`  
  https://huggingface.co/unitary/multilingual-toxic-xlm-roberta

### 10.3 KOLD — 한국어 offensive language에서 macro-F1의 중요성

KOLD 논문은 한국어 offensive language dataset을 제시하며, offensive 여부 외에 target-related multi-level 분류를 다룬다. 논문에는 하위 분류 과제에서 **macro-F1**을 사용하며, 라벨 구조가 세분화될수록 성능이 크게 어려워짐을 보여준다.

시사점:
- DKTC도 단순 binary detection보다 세분화된 5-class 과제라서 macro-F1이 중요하다.
- 현재 일반대화 F1이 매우 높다고 안심하면 안 되고, `기타괴롭힘` 같은 약한 클래스가 전체 경쟁력을 깎는다.
- 즉 지금처럼 macro-F1 중심으로 의사결정하는 방향은 맞다.

출처:
- EMNLP 2022, *KOLD: Korean Offensive Language Dataset*  
  https://aclanthology.org/2022.emnlp-main.744.pdf

### 10.4 한국어 offensive/hate corpus 확장 사례 — 라벨 품질과 노이즈 완화

2023년 한국어 offensive corpus 관련 연구에서는 대규모 데이터셋 구축과 함께 **주석 노이즈와 편향 문제**, **라벨 품질 개선 필요성**을 강조한다.

시사점:
- 현재 DKTC 성능 병목이 `기타괴롭힘`처럼 경계가 넓은 클래스에 몰린 것은 모델만의 문제가 아닐 수 있다.
- 즉 추가 개선은 하이퍼파라미터보다 **라벨 경계 정의/샘플 품질/규칙 후처리**가 더 중요할 수 있다.

출처:
- Findings of EMNLP 2023, *A Hate Speech Detection Corpus in Korean with Target-Specific Ratings*  
  https://aclanthology.org/2023.findings-emnlp.952.pdf

## 12. 최종 결론

이번 세션에서 확인된 핵심은 다음과 같다.

1. 현재 데이터와 `klue/roberta-base` 조합은 이미 강한 수준의 베이스라인을 형성했다.
2. baseline 대비 최종 최고점은 **Macro F1 +0.0154** 개선되었다.
3. Focal Loss 실험 공간에서 최고점은 `focal_epoch_5`였고, 전체 최고점은 **0.9301 macro F1**이다.
4. 하지만 진짜 병목은 여전히 **괴롭힘 내부 경계**, 특히 `기타괴롭힘`이다.
5. 다음 단계의 핵심은 더 많은 하이퍼파라미터 탐색이 아니라:
   - 최고 성능 후보 3개 유지
   - 규칙 기반 후처리는 보조 후보 수준으로 유지
   - 2단계 분류 프로토타입 우선 구현
   - CV 안정화
   - 필요 시 도메인 적응/앙상블
   로 정리된다.

이 문서를 기준점으로 삼으면, 다음 세션에서는 같은 실험을 반복하지 않고 **현재 병목에 직접 타격하는 개선**부터 이어갈 수 있다.
